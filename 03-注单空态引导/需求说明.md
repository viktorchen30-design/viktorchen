H5／APP「注单」页面当前在所选 TAB 没有注单数据时，仅展示空状态，用户缺少下一步操作入口。本期在 **场馆A／场馆B注单无数据空状态** 替换三语文案，并增加 **「立即投注 / Bet Now / Cược ngay」** 按钮；点击后按注单页当前选中的 **场馆A／场馆B**，走 **首页顶栏进馆路由** 进入对应原生场馆页。  
**【重要】无后台配置、与「顶部 icon 可配置」需求无关联。**只改 场馆A／场馆B 的无数据空状态；有注单时维持现有展示逻辑，不增加额外引导。范围为 **H5／APP · 中国站／越南站／国际站**。  
**【重要】本需求在 UI 改版之后再开启。** 正文逻辑先定；当前附图／原型基于 **改版前旧 UI**，仅表达空状态文案与按钮关系。改版后会 **重新上传原图**，并 **按新图重做原型**；开发／验收以改版后原图 + 更新后的原型为准。  
**【重要】「立即投注」跳的是原生场馆页**，路由与 **首页顶栏 场馆A／场馆B 进入原生场馆** 同一套；**不是**注单页顶部用来切换「看哪边注单」的 场馆A／场馆B Tab。  
**【重要】未登录进不了注单页**：点底部导航「注单」（及其他进注单入口）走现网 **登录弹层**；**登录成功后进入主页面（首页）**，不会直接落在注单。要看注单须 **再次点击** 底栏「注单」。本期空状态与「立即投注」仅在 **已登录且已进入注单页** 后出现。

## 业务速览（业务需关注 · 约 2 分钟）

### 用大白话说

用户进入「注单」后，如果当前 TAB 没有记录，现在只能看到空状态，页面没有可继续操作的方向。

本期替换空状态文案并增加 **「立即投注」** 按钮。用户点击后，当前选中 场馆A就进入 **场馆A原生场馆页**，当前选中 场馆B就进入 **场馆B原生场馆页**（与首页顶栏进馆同一路由，不是切注单 Tab）。

:::ok
**你可以这样理解：**

- **现在**：注单 TAB 无数据 → 只看到空状态，下一步要自己找场馆。
- **改完后**：注单 TAB 无数据 → 显示「暂无数据／前往查看精彩赛事」及「立即投注」按钮。
- **点击按钮**：跳到当前选中馆的 **原生场馆页**（与 **首页顶栏** 场馆A／场馆B 进馆同一路由）。**不是**再点注单页顶部 场馆A／场馆B（那是切注单列表，人还在注单页）。
- **有注单时不变**：正常展示注单列表，不显示空状态引导。
- **只做引导，不自动跳转**：用户主动点击后才离开注单页。
- **APP 自己跳**：APP 不复用 H5 页面，由客户端按首页顶栏进馆同一套自行跳转。
- **只涉及 场馆A／场馆B**：其他游戏没有本需求所述的注单无数据界面；**顶部切到「游戏」维持现网空状态，不做本期引导、不出「立即投注」**。
- **无后台配置**：前端直接按当前顶部选中项跳转；与「顶部 icon 可配置」需求无关联。**本期无 BE、无新接口、无埋点。**
- **未登录进不了注单页**：点底栏「注单」等入口会弹出 **要求登录**；**登录成功后进主页面（首页）**，不会直接进注单。要进注单须再点一次底栏「注单」。因此「立即投注」只给已登录且已在注单页的用户看。
- **页内登录失效**：踢登录；重新登录后同样进 **主页面**，不会留在注单、也不会自动点「立即投注」。
- **所有进注单入口同一套**：底栏、投注成功进注单、我的、推送／深链等，只要落在 场馆A／场馆B 且该 TAB 无数据，都走本期空状态。
- **场馆限制不拦本次跳转**：H5／APP 原生场馆正常展示；进入后用户真正下注时，再按既有限制逻辑判断并给出对应结果。
- **三站三语**：中国站中文、国际站英文、越南站越南文。
- **H5／APP 都要覆盖**。
- **排期**：等 **UI 改版完成后再开**；下面附图是旧版，改版后换图并重调原型。
:::

## 背景与目标

### 现状

1. 用户进入注单页面后，按 TAB 查看对应注单。
2. 当前 TAB 返回空数据时，页面仅展示既有空状态。
3. 空状态没有直接前往体育场馆的入口，用户需要自行切换页面寻找赛事。

### 目标

1. 给无注单用户一个清晰、可操作的下一步。
2. 缩短从「无注单」到「浏览赛事／投注」的路径。
3. 不影响已有注单用户查看记录、切换 TAB 与执行原有操作。

## 核心规则

| # | 规则 | 说明 |
| --- | --- | --- |
| 1 | 展示条件 | **当前场馆 + 当前 TAB** 的注单列表接口 **成功返回空数组（0 条）** 时，展示空状态文案与按钮；与页上「总计 0 单」应对齐。本期无额外筛选空态 |
| 2 | 有数据不展示 | 当前 TAB 有任意注单时，仅展示既有注单列表，不显示本期引导 |
| 3 | 各 TAB 独立判断 | 切换 TAB 后，以新 TAB 自身的数据结果重新判断 |
| 3b | 所有进注单入口 | 底栏／投注成功／我的／深链／推送等，只要落在 场馆A／场馆B 且该 TAB 无数据，均走本期空状态 |
| 4 | 用户主动跳转 | 不自动跳场馆；仅点击「立即投注」后跳转 |
| 5 | 按当前选中馆跳原生场馆 | 注单页顶部当前选中 场馆A → 进 **场馆A原生场馆页**；选中 场馆B → 进 **场馆B原生场馆页**。由前端直接判断，无后台配置 |
| 5b | 【重要】场馆上下文一致 | 停留在哪个场馆，空状态判断、按钮展示、跳转目标就必须是哪个场馆。注单页顶部选中项、当前 TAB 数据结果、跳转目标三者必须同一场馆；旧请求不得覆盖新场馆 |
| 5c | 【重要】进馆路由 ≠ 注单 Tab | 点击「立即投注」＝走 **首页顶栏 场馆A／场馆B 进入原生场馆** 的既有路由与落点。**禁止**做成再点注单页顶部 场馆A／场馆B（那只切换注单列表，人仍在注单页） |
| 5f | APP 跳转 | **客户端自行跳转**，不复用 H5 页面；目标与该端首页顶栏 场馆A／场馆B 进馆一致 |
| 5d | 打开注单时的默认馆 | **与现网注单页顶部默认选中一致**；按钮只认打开后顶部 **实际选中项**，本期不另定默认馆 |
| 5e | 顶部「游戏」 | **维持现网**，不出本期文案与「立即投注」 |
| 6 | 不改查询逻辑 | 不修改注单接口、筛选条件、状态分类与列表出数 |
| 6b | 无后端 | **本期无 BE、无新接口、无后台配置** |
| 6c | 无埋点 | **本期不新增任何埋点**（空状态曝光、按钮点击、跳转目标场馆均不做） |
| 7 | 加载不等于空数据 | 请求未结束时展示既有加载态，不提前展示空状态引导；**请求完整成功返回 0 条后才出按钮** |
| 7b | 切场馆先清旧空态 | 顶部 场馆A／场馆B 切换后、新场馆数据未返回前：展示加载态；**不得沿用上一场馆的空状态与按钮** |
| 8 | 失败不等于空数据 | 接口失败沿用既有失败／重试表现，不误判为空数据 |
| 10 | 三站文案 | 按站点固定：中国站中文、国际站英文、越南站越南文，按下表定稿展示 |
| 11 | 空状态图跟改版走 | **插图／空状态视觉以 UI 改版设计为准**；本期只 **替换标题／说明并加按钮**，不沿用改版前旧图标另画一套 |
| 12 | 其他页面元素 | 总计、公告、顶部导航、底部导航及其他既有元素均保持现状 |
| 13 | 场馆限制 | 已登录点击允许正常进入对应原生场馆；进入后发生下注时，才按既有场馆限制逻辑判断并提示 |
| 13b | 未登录 | 点底栏「注单」等入口 → 现网登录弹层。**登录成功进入主页面（首页）**，不直接进注单；须再点底栏「注单」才进注单页。未登录看不到本期空状态，点不到「立即投注」 |
| 13c | 页内登录失效 | **踢登录**；重新登录后进入 **主页面**，不留在注单、不自动跳原生场馆、不自动触发「立即投注」 |
| 14 | 防重复点击 | 点击「立即投注」后按技术常规防重复触发（建议 **3～5 秒**，以研发既有标准为准），避免连点叠开多层同一场馆 |
| 15 | 跳转失败 | 复用 **首页顶栏进馆** 既有失败处理；**不做持续轮询自动再跳**（见「弱网／接口异常」） |
| 16 | APP 灰度 | **无新接口**。APP 由客户端自行跳转，须发版。灰度期内 **旧包维持改造前空状态（无「立即投注」）**，新包走本期；旧包不崩、不脏数据 |

## 交互流程

```text
进入注单页／切换 TAB／切换顶部 B·DB
        ↓
以「当前场馆 + 当前 TAB」为上下文请求注单
        ↓
┌─ 加载中／切场馆未返回：展示既有加载态（清掉上一场馆空态与按钮）
├─ 请求失败：展示既有失败／重试
├─ 有数据：展示既有注单列表，不加引导
└─ 本场馆本 TAB 请求完整成功且 0 条：空状态文案 +「立即投注」
                         ↓ 用户点击（防重复 3～5 秒）
             走首页顶栏 场馆A／场馆B 进馆路由 → 对应原生场馆页
             （不是切注单页顶部 Tab）
```

**【重要】停留在哪个场馆，跳转就必须是哪个场馆。** 空状态判断、顶部选中项、跳转目标必须同一场馆上下文。  
**【重要】进馆 ≠ 切注单 Tab。** 按钮走 **首页顶栏 场馆A／场馆B 进原生场馆** 的路由，不要做成再点注单页顶部 场馆A／场馆B。  
该按钮与「顶部 icon 可配置」需求无关联。
:::

## 弱网／接口异常

拆成两段，**不要用持续轮询兜底**。

### A. 注单数据还没出来（按钮还没出现）

网速慢、接口慢，属于「这次请求还没结束」，不是跳转失败。

| 情况 | 怎么处理 |
| --- | --- |
| 接口慢、弱网还在转 | **只出既有加载态**；等 **当前场馆 + 当前 TAB 这一次请求** 完整结束。不另开轮询、不提前出「立即投注」 |
| 接口超时／失败 | **走注单页既有失败／重试**（用户点重试再拉一次）。失败 ≠ 无数据，**不出空状态按钮** |
| 请求成功且 0 条 | 这时才替换文案并出「立即投注」 |
| 请求成功且有数据 | 只出列表，本期不动 |

### B. 已经点了「立即投注」，进场馆慢或失败

按钮复用 **首页顶栏 场馆A／场馆B 进馆** 路由，**弱网表现与点首页顶栏进馆保持一致**。

| 情况 | 怎么处理 |
| --- | --- |
| 跳转过程慢（转圈／白屏） | 沿用首页顶栏进馆既有等待；按钮进入防重复（3～5 秒或技术常规），避免连点叠页 |
| 跳转失败／超时／路由打不开 | **人留在注单页**；失败提示与点 **首页顶栏 场馆A／场馆B 进馆** 失败 **同一套**（有 Toast 就同一句，现网没提示则本期也不新造文案） |
| 用户要再试 | **再点一次按钮**（防重复结束后）。不后台自动再跳 |
| 技术瞬时重试 | **允许**：点击当次内部按惯例重试 1～2 次（跟首页顶栏进馆实现对齐即可） |
| 定时轮询直到跳成功 | **不做** |

:::ok
**产品一句话**：网慢就等这一次；失败就按现网失败／重试，人还在注单页，要再进场馆就再点按钮。不要偷偷轮询把人拉走。
:::

## 异常与边界

| 场景 | 预期 |
| --- | --- |
| 首次进入仍在加载 | 不展示空状态引导 |
| 接口超时／失败 | 展示既有失败或重试，不展示无数据引导 |
| 当前 TAB 无数据、其他 TAB 有数据 | 当前 TAB 显示引导；切到有数据 TAB 正常展示列表 |
| 快速切换 TAB | 以后一次有效请求对应的 **当前场馆 + 当前 TAB** 为准，避免空态串页 |
| 快速切换顶部 场馆A／场馆B | 立刻进入加载态并清掉上一场馆空态／按钮；仅新场馆请求完整成功且 0 条后，才出对应按钮 |
| 旧请求晚到 | **丢弃**；不得用 B 的空结果在已选中 DB 的页面出按钮（反之亦然） |
| 点击时场馆维护 | 进入行为沿用 **首页顶栏进馆** 的既有维护机制 |
| 用户受到场馆限制 | 已登录允许进入原生场馆；下注时再按既有限制逻辑判断并提示 |
| 未登录点底栏「注单」（及其他进注单入口） | 现网登录弹层；**登录成功进主页面**；须再点「注单」才进注单页；看不到本期空状态 |
| 页内登录失效后点「立即投注」或被踢 | 踢登录；重新登录后进 **主页面**，不留在注单、不自动进场馆 |
| 已登录点「立即投注」 | 走首页顶栏进馆路由，直接进对应原生场馆页，不再弹登录 |
| 顶部切到「游戏」 | 现网空状态，无本期按钮 |
| 非底栏入口进入注单 | 与底栏进入同一套空状态规则 |
| 快速切换顶部 场馆A／场馆B 后点击 | 以点击按钮当下顶部实际选中项为准，避免跳到切换前场馆 |
| 连续点击「立即投注」 | 防重复（3～5 秒或技术常规），只触发一次跳转 |
| APP 灰度旧包 | 无新接口、不崩；旧包维持改造前空状态（无本期按钮）；新包客户端自行跳转 |
| 跳转失败 | 首页顶栏进馆既有失败处理；可有限次即时重试；不轮询自动再跳 |

## 风险评估

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 做成切注单 Tab | 点按钮人还在注单页 | 必须走首页顶栏进原生场馆路由 |
| 切场馆沿用旧空态 | 画面已是 DB，按钮仍按 B 的空结果可点 | 切场馆先清空态；请求完整成功才出按钮 |
| 加载态误判为空态 | 页面先闪引导再出列表 | 等接口成功返回空集合后再展示 |
| 连点叠开多层 | 同一场馆打开多次 | 防重复 3～5 秒或技术常规 |
| 跳转失败轮询自动再跳 | 用户已停在注单却被突然拉走 | 复用首页顶栏进馆失败处理；禁止持续轮询 |
| APP 与 H5 路由不一致 | 某端跳转失败 | 各端分别复用 **本端** 首页顶栏进馆；APP 不复用 H5 页；提测前两端对一下 |
| 多语言换行或溢出 | 越南文展示不完整 | UI 按最长越南文走查并做小屏适配 |
