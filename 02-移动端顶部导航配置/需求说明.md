:::lead
H5／APP 首页顶部导航（场馆B、场馆A、游戏、直播）当前 icon／文案调整成本高。本期在管理后台 **网站配置** 新增 **顶部导航配置**：运营可按 **三站**、**H5／APP 分端**、**日间／夜间**、**未选中／选中** 上传 icon 并维护名称；用户端按后台返回参数正确展示。  
**【重要】H5 与 APP 布局一致**；**不含 PC**。  
**【重要】本期只配 icon 图与名称**：本需求 **不借配置去改** 各格点击跳转／选中／业务能力；**不得因可配置而拦功能**。  
**【重要】四格内容固定**：用户端始终这四项（场馆B／场馆A／游戏／第 4 格），**本功能只配图／名称**；**场馆B／场馆A 展示顺序**由「导航排序」等另功能负责，本页不展示、不操作排序；图／名按 `navItemCode` 绑定。  
**【重要】中国站第 4 格 · 近期另有变动（仅注明）**：**本需求不写**该变动的具体内容。改版／变动时须 **另行留意** 是否与本配置逻辑关联（如 `live`／`square` 双套、按账号取套、图＋名下发、防闪／破图兜底等），避免互相踩坑；**与本期范围无关，只作关联提醒**。改版后 **icon／名称仍须走本后台配置**，不得改回写死。  
**【重要】第 4 格 · 仅中国站**：账号分 **有直播／无直播**，后台须提供 **两套配置位** 加以区分（业务上常见为 **直播** 与 **广场**；列表类型标识能区分即可）。用户端第 4 格只出一格，按账号类型取对应套；**展示名称、图片均以后台接口为准**（名称本身不绑死文案）。越南站／国际站 **无此区分**，第 4 项仍 **一套**。
:::

### 用大白话说

移动端头顶那一排：**场馆B、场馆A、游戏、直播**（图标 + 文字）。现在不好随时换图／改名。本期让运营在 **后台** 配好，**中国站／越南站／国际站** 都能配；**H5 和 APP 布局一样**，但 **图要分开传**；还要分 **白天／夜间**、**选中／没选中**。用户打开时按后台下发显示。

:::ok
**你可以这样理解：**

- **现在**：顶部导航 icon／名称偏写死或难配，换图要发版。  
- **改完后**：网站配置里有 **「顶部导航配置」** → 上传图、改名称 → H5／APP 按返回参数展示。
- **【重要】只改「长什么样」，本需求不改「怎么用」**：本期可配的是 **icon 图 + 名称**；**不能**因配置图／名而拦点击、改跳转、影响正常使用。四格内容固定，**排序不在本功能**（另有「导航排序配置」可调 场馆B／场馆A 位置）。图／名按业务标识 **`vb`／`va`／`game`／`live`／`square`** 绑定，调位也不会图错。  
- **【重要】已展示就不换（防闪）**：四个顶栏格子 **一旦已经画出来**（常见：因接口慢先出了默认图），本页内 **不再换成后台图**，避免一闪一闪。若稍后接口成功拿到后台配置 → **只写入本地缓存，当面界面不动**。只有 **H5 刷新**，或 **切走底部 Tab 再回到本页**（APP：再进首页／杀进程重开同理），才用缓存（或再请求）展示最新图／名。日夜主题切换除外（只换已有日／夜资源）。  
- **【重要】中国站第 4 格 · 近期另有变动（仅注明，非本期范围）**：**不在本需求里写变动内容**。做那次改版时，请核对是否动到：有／无直播双套、`live`／`square`、按账号取第 4 格皮、点击跳转、防闪／破图兜底等；有关联则在 **该改版需求** 里处理，避免和本期配置打架。无论怎么变，**图＋名仍须用本后台配置**。  
- **前三项固定**：场馆B、场馆A、游戏（不能增删；暂不做显隐开关）。  
- **第 4 项「直播」要分站看**：  
  - **中国站**：账号有／无直播 → 后台 **两套配置**，但列表 **只占一行**；点【编辑】**同一页上下同时展示**「有直播配置」与「无直播配置」（名称、图各配，不分 Tab）。用户端第 4 格仍只出一格。  
  - **展示名称、图片**：都由后台配置／接口提供，**不必写死叫什么**。  
  - **有／无直播怎么判**：由 **账号侧既有能力判断**；本需求只约定映射（有→有直播套，无→无直播套），**不深究判定公式／字段实现**。  
  - **越南站／国际站**：**没有**这套账号区分 → 第 4 项仍只配 **一套**。  
- **三站都要**；各站图各自配。名称语言：**中国站中文**；**越南站越南文**（不做多语言切换）；**国际站暂定英文**。  
- **H5＝APP 布局**；配图 **必须分端**；日夜＋选中态 → 每一配置行 **8 张图**。  
- **读不到配置／上线还没配／破图怎么办**：网络差、接口挂、后台空配置时 → 配置 → 缓存 → **端内默认**；**不能空白、不能崩、不能裂图**。单张 CDN 破图 → **只换该态默认图**，名称尽量保留。已画出后晚到配置／好图 → **当面不闪**。默认图＝改造前写死资源，**本期不拉 UI**。  
- **不改 PC**；不对齐「游戏类型配置」。
:::

### 用户端 · 读配置失败怎么办（【重要】）

:::critical
拉后台配置 **一定会遇到**：弱网、超时、接口 5xx、返回空／缺字段、解析失败、图片 CDN 挂、**破图**等。产品口径必须先定死，避免研发各端各做一套。  
**总原则**：顶栏 **始终 4 格可点**；**不空白、不破图、不崩、不堵死弹窗、不因兜底改跳转**；体验上尽量 **静默、不闪、不跳布局**。
:::

#### 1）配置数据从哪来（优先级）

| 优先级 | 何时用 | 展示什么 | 用户侧体感 |
| --- | --- | --- | --- |
| 1 | 本次拉配置 **成功**，且本页顶栏 **尚未画出** | 用本次返回渲染四格；并 **写入本地缓存**（键见实现必盯） | 正常看到后台图／名 |
| 1b | 本次拉配置 **成功**，但本页顶栏 **已经用默认／旧图画出** | **只写／覆盖缓存，本页界面不换**（防闪）；刷新或底 Tab 再进后再用缓存 | **当面不闪换**；再进页才变新 |
| 2 | 本次拉配置 **失败**，但本地有上次成功缓存 | 用 **缓存** 渲染 | 仍有完整顶栏；可能略旧于后台，可接受 |
| 3 | 失败且 **无缓存**，或后台 **无有效配置**（含上线未配） | 用 **端内默认** 画出四格（中国站第 4 格按有／无直播用对应默认） | 看起来像改造前写死顶栏；功能正常 |
| 4 | 配置／缓存已有，但 **某张 icon 图加载失败（破图）** | 见下节「破图／单图失败」 | **禁止出现裂图／空白方块** |

#### 2）接口／数据类失败（怎么判、怎么应对）

| 场景 | 判定示例 | 应对 | UX 要求 |
| --- | --- | --- | --- |
| 弱网／超时 | 请求超时、长时间无响应 | 有限重试后 → 缓存 → 默认；**不堵首屏** | 顶栏尽快用缓存／默认画出，其它模块照常加载 |
| 接口 4xx／5xx／网络断 | HTTP 失败、无网 | 同上 | **不弹**必须点掉才能进首页的错误框；不 Toast 打断 |
| 返回空／全空数组 | body 空、无四项 | 当「无有效配置」→ 缓存 → 默认 | 四格仍在，用默认名＋默认图 |
| 缺字段／少一项 | 缺某 `navItemCode`、缺名称或某态 URL | **缺哪项补哪项默认**；已有项尽量用返回值 | 不要整排回退成默认（避免「一个字段坏全盘默认」） |
| 解析失败／结构异常 | JSON 坏、类型错 | 当失败 → 缓存 → 默认 | 不崩、不白屏 |
| 缓存损坏／读不出 | 本地反序列化失败 | 清该缓存键，当无缓存 → 默认 | 静默；下次成功再写缓存 |
| 老包无新接口 | 无接口／缺字段 | 当无配置 → 端内默认／旧写死 | 不因强解析新字段崩溃 |
| 上线后台未配 | 运营尚未保存有效配置 | 走默认（有缓存仍优先缓存） | 允许；不强制上线前回填 |
| 中国站只配一套 | 仅 live 或仅 square 有效 | 缺的那套账号类型走默认；已配套照常 | 一类账号正常、一类像改造前 |

#### 3）破图／图片加载失败（【重要】· 用户最容易感知）

:::warn
**破图**＝ CDN 404、加载超时、图片损坏、非图内容、跨域失败、URL 空字符串等，导致 `<img>` 失败或画不出。  
**禁止**：浏览器默认裂图图标、灰色空框、图标位塌成 0 高、整格空白。
:::

| 场景 | 应对 | UX 要求 |
| --- | --- | --- |
| **单张**配置／缓存 URL 加载失败 | **仅该格、该端、该主题、该选中态** 换用 **端内默认图**；名称若已有配置文案则 **仍用配置名称** | 其它格不受影响；格子尺寸不变、不跳布局 |
| **某一格多态**（如仅夜间选中）挂了 | 只换挂掉的那一态默认图；日间／未选中仍用配置 | 切日夜／点选中时，失败态也不破图 |
| **四格图全部** CDN 挂 | 四格图都走默认；名称能取配置则取配置 | 顶栏仍完整可点，像写死默认 |
| **有 URL 但图极慢** | 允许先显示默认图占位，或保持上一帧；**不要**长时间空白等图 | 首屏顶栏 **尽快有图**；慢图回来若本页已画出 → **本页不闪换**（写入策略同防闪，再进页可用） |
| **名称有、图无／图挂** | 名称用配置；图用默认 | 文案对、图标不破 |
| **图有、名称为空／缺** | 图用配置；名称用该 `navItemCode` 的 **端内默认名** | 不出现「有图无字」或空白文案 |
| **破图后 URL 重试成功** | **本页内不跳变回配置图**（与防闪一致）；刷新／底 Tab 再进后再用 | 避免裂图→默认→再闪成配置图 |
| **默认图自身缺失（研发事故）** | 须上线前保证默认资源打进包；验收卡死 | 若极端缺失：至少保留文字名称＋可点热区，**仍禁止裂图占位** |

:::ok
**破图处理一句话**：失败就换 **同代号端内默认图**，保格子、保可点、保不裂；**不要**让用户看到破图。
:::

#### 4）用户体验总约束（读配置／破图共用）

| # | 约束 | 说明 |
| --- | --- | --- |
| U1 | **静默兜底** | 读配置失败、破图兜底 **不**弹堵死框；不因顶栏失败打断进首页 |
| U2 | **始终 4 格** | 布局不因失败变成 3／5 格或高度塌陷 |
| U3 | **可点可跳** | 配置／缓存／默认／破图兜底时，点击、跳转、选中逻辑 **与改造前一致** |
| U4 | **不闪不跳** | 已画出后本页不因晚到配置／晚到好图而闪换（日夜切换除外） |
| U5 | **尽快有内容** | 弱网时优先用缓存或默认 **尽快画出**，避免顶栏长时间空洞 |
| U6 | **日夜／选中仍可用** | 走默认时也要有日夜、选中／未选中对应默认图，切换主题不破图 |
| U7 | **不阻塞首屏** | 顶栏配置请求失败不拖死首页其它模块 |
| U8 | **与启动页隔离** | 缓存键、防闪策略不与启动页兜底图串用 |

| 补充约定 | 说明 |
| --- | --- |
| 有／无直播判定 | **由账号侧既有能力判断**；本需求只写映射，**不展开判定字段／公式** |
| 与「上传失败」区别 | 上表管 **用户端读配置／破图**；运营后台上传失败仍见「上传失败文案」节 |

### 端内默认图（【重要】）

:::ok
**已确认**：当前 H5／APP 顶栏 **图和名称都是写死的**，包内 **已有现成资源** → **直接当作端内默认**，研发整理内置即可。**本期默认图不需要拉 UI**（对齐「先对包里有没有现成图；没有再拉 UI」——现已确认有）。  
默认资源同时服务：**无配置、接口失败、缓存没有、破图替换**。
:::

| 项 | 说明 |
| --- | --- |
| 要什么 | H5／APP 包内自带默认 **图＋名称**，覆盖：三站、分端、日夜、选中／未选中；中国站第 4 格还要有有直播／无直播两套默认 |
| 来源（已确认） | **改造前已写死在用的切图／文案**；H5／APP 研发收成「无配置／失败／破图」兜底路径 |
| 要不要 UI | **本期默认图：不需要 UI**。仅当以后要换一套 **新默认视觉** 时，再请 UI 出资源（72×72、日夜／选中态；非整页改版） |
| 上线策略 | 后台可以先空着；用户端走上述默认。运营后续配好后，用户刷新／底 Tab 再进即可看到配置图 |
| 破图时 | 用 **同 navItemCode、同端、同主题、同选中态** 的默认图替换；名称优先保留配置文案 |

:::key
【注意】主口径两句：  
1）**配置链路**：成功用配置 → 失败用缓存 → 再无用默认。  
2）**体验链路**：先画出（缓存／默认）→ 晚到只进缓存当面不换 → **破图立刻换默认、禁止裂图** → 刷新／底 Tab 再回才用最新缓存。
:::
